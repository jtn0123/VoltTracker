## Findings

| # | Area | Layman explanation | Evidence | Impact | Ease |
|---|------|--------------------|----------|--------|------|
| 1 | Backup during logging | A user can export a backup while live OBD writes are still happening, so the copied database can miss recent WAL data or capture a half-updated trip. | `BackupController.java:45-58` starts backup without checking `MainActivity.isLoggingActive`; `DataBackup.java:150-172` checkpoints and copies the DB file; `ObdStoreMaintenance.java:103-112` logs checkpoint failure but lets backup proceed. | High | Medium |
| 2 | Clear storage during logging | The dashboard can wipe all local tables while the OBD service keeps writing the same active session, producing broken or misleading trip history. | `VoltBridge.java:192-217` runs clear in the background with no active-session guard; `ObdStoreMaintenance.java:32-55` deletes session, telemetry, location, event, and rollup tables. | High | Medium |
| 3 | Shared backup cleanup | Shared backup files are deleted after one hour even if an external share target has not finished reading the granted URI. | `BackupController.java:129` schedules cleanup after launching share; `BackupController.java:435-438` deletes the shared file after one hour. | Medium | Easy |
| 4 | Encrypted restore size cap bypass | A small encrypted file can decrypt into a huge staged SQLite file because only the input file is size-limited before decryption. | `DataBackup.java:40` caps restores at 128 MiB; `DataBackup.java:214-238` enforces the cap while copying the picked URI; `DataBackup.java:239-254` decrypts into a candidate file without applying the same cap. | High | Medium |
| 5 | Session persistence disabled by JSONL failure | If the black-box JSONL log cannot open, the recorder never starts the SQLite session, so telemetry, status, and GPS persistence silently stop even while the service keeps running. | `SessionRecorder.java:104-170` returns before `localStore.startSession` when `sessionLog.isOpen()` is false; `SessionRecorder.java:383-430` drops telemetry/status/location when `activeSessionId <= 0`. | High | Medium |
| 6 | OBD loop crash leaves service alive | A runtime exception in the polling task broadcasts an error but does not stop the foreground service or foreground notification path. | `ObdPollingEngine.java:399-407` catches `RuntimeException` and only broadcasts status before returning; `ObdService.java:459-473` stops foreground state only through normal stop paths. | High | Medium |
| 7 | Start-session executor race | `startSession` marks the app active, starts foreground mode, opens logging, and then submits work to the executor with no catch, so a late submit during shutdown can leave active state half-set. | `ObdService.java:395-424` mutates session state before `executor.submit`; `ObdService.java:301-307` shuts the executor during destroy. | Medium | Medium |
| 8 | Bluetooth permission race | Bonded-device reads can throw after the permission check if the user revokes Bluetooth permission in Settings between check and use. | `DeviceCatalog.java:54-90` checks permission, then calls `adapter.getBondedDevices`, `device.getName`, and `device.getAddress` without catching `SecurityException`. | Medium | Easy |
| 9 | Inflated adapter history | A single Connect or Scan click can remember the selected adapter twice, inflating connect counts and last-used metadata. | `actions.js:74-87` calls `bridge.rememberDevice` before `bridge.connect` or `bridge.scan`; `VoltBridge.java:104-124` remembers again in both native bridge methods; `DeviceCatalog.java:226-267` increments history counts. | Medium | Easy |
| 10 | Invalid stored adapter address | The native catalog accepts any nonblank address, so an invalid Bluetooth address can be saved and later offered as the resume target. | `DeviceCatalog.java:157-170` persists any nonblank address; `VoltBridge.java:226-245` uses the stored/candidate device for resume; `ObdPollingEngine.java:524-529` only rejects invalid addresses later. | Low | Easy |
| 11 | Repeated location prompts | The permission gate can keep asking for fine location even after a user granted approximate location, although later checks treat either fine or coarse as enough. | `PermissionGate.java:44-50` runs connection and location requests together; `PermissionGate.java:67-73` requests both fine and coarse when fine is missing; `PermissionGate.java:89-92` accepts either permission as location-capable. | Low | Easy |
| 12 | Stale telemetry accepted forever | Once the database has any rows, the dashboard accepts `latestTelemetry` regardless of age, so old speed/SOC/voltage can repopulate live tiles as if current. | `telemetry.js:57-84` accepts telemetry when `dbRowCount(state.storage || {}) > 0`, independent of `updatedAt` age. | High | Easy |
| 13 | Live session totals carry across drives | Because stale telemetry is accepted and reset is not tied to a new real session, distance and SOC baselines can continue from a previous drive. | `telemetry.js:91-114` resets only through `resetTelemetry`; `telemetry.js:303-339` initializes `sessionStartSoc` once and keeps accumulating `sessionDistanceM`. | High | Medium |
| 14 | Stale PID values re-emitted as current | The polling reader builds new samples from the last raw value for many PIDs even when that PID was not polled in the current cycle, so dashboard values can look fresh when they are old. | `LiveSampleReader.java:57-97` reads speed, RPM, coolant, load, SOC, pack voltage, current, and battery temp from `lastRaw`; `LiveSampleReader.java:99-103` only adds stale age fields for a subset. | Medium | Medium |
| 15 | Clear-DTC result not recorded | The clear-code command broadcasts a result sample, but the storage layer rejects samples unless they contain driving telemetry fields, so clear-code success/failure can vanish from history. | `ClearDtcRunner.java:74-88` emits `clearDtcOk`, `clearDtcCode`, and raw result; `ObdStoreWriter.java:136-140` skips samples that fail `isUsefulTelemetry`; `ObdStoreSupport.java:252-268` does not treat clear-DTC fields as useful. | Medium | Easy |
| 16 | VIN scan update races shutdown | Diagnostic scan VIN persistence is queued asynchronously after the scan, so it can race session finalization or store closure and be lost with only a log message. | `DiagnosticScanRunner.java:100-105` submits `store.upsertVehicleFromVin` via `recorder.runAsync`; `SessionRecorder.java:183-275` can close/finalize the session independently. | Medium | Medium |
| 17 | Protocol init can continue after failed PID probe | The ELM initialization path logs protocol init as okay even if the standard `0100` probe never returns a prompt, then moves on to live probing. | `ObdPollingEngine.java:563-613` retries protocol setup and logs `protocol_init` without failing when the fallback `0100` still has no prompt. | Medium | Medium |
| 18 | Map loses older valid drives | The Map tab only looks at the latest eight sessions before filtering for route points, so a few recent failed/no-GPS sessions can hide older route-bearing drives. | `ObdStoreReports.java:223-229` requests `recentRoutes(db, 8, 500)`; `ObdStoreRouteProjection.java:65-84` skips sessions with fewer than two route points. | High | Easy |
| 19 | Trips list loses older valid trips | The Trips tab inspects only the latest 100 sessions before sorting and limiting, so many recent failed or scan sessions can push real older drives out of view. | `ObdStoreTrips.java:42-68` calls `getRecentSessions(db, 100)`, filters after that, then sorts and applies the requested limit. | Medium | Easy |
| 20 | Map drive stats use raw session tails | Map duration and average speed use the raw session start/end instead of the drive-window split used for Trips, so parked tails can inflate map stats. | `map.js:155-163` computes duration and average from `route.session.startedAtMs` and `endedAtMs`; `ObdStoreRouteProjection.java:65-84` projects full sessions for recent map routes. | High | Medium |
| 21 | Telemetry-only tail trimmed | Drive-window bounds prefer location samples when any exist, so a session where GPS stops early but telemetry continues can lose the tail of the drive. | `DriveWindowDetector.java:129-145` returns location bounds before telemetry bounds. | Medium | Medium |
| 22 | Sparse GPS blocks richer telemetry route | Route splitting ignores telemetry latitude/longitude whenever location-sample rows exist, even if those rows are sparse and telemetry has the better route. | `DriveWindowDetector.java:171-186` reads only `location_samples` when they exist; `ObdStoreRouteProjection.java:116-164` similarly prefers location points over telemetry fallback. | Medium | Medium |
| 23 | Slow traffic can be cut as a stop | The stop splitter treats slow movement under 2.5 m/s across 300 meters for three minutes as a stop, which can remove crawling traffic or parking-lot movement from a trip. | `DriveWindowDetector.java:91-127` marks GPS stop spans from slow speed, low path distance, and duration thresholds. | Medium | Hard |
| 24 | Pruning leaves stale derived trips | Raw-data pruning deletes telemetry, location, event, and PID rows but leaves rollups and trip segments, so summaries can keep reporting trips whose raw evidence is gone. | `ObdStoreMaintenance.java:81-100` preserves `session_trip_rollups` and `trip_segments`; `ObdStoreTrips.java:290-300` considers a rollup fresh by version only. | Medium | Medium |
| 25 | Dashboard reads can rebuild every session | Storage summaries and insights can trigger rollup computation over all sessions during a read, creating a slow dashboard path on large databases. | `ObdStoreReports.java:471-473` calls trip distance during summary generation; `ObdStoreTrips.java:177-184` and `ObdStoreTrips.java:275-288` ensure rollups by scanning sessions. | Medium | Hard |
| 26 | Bad nested JSON empties storage summary | One JSON exception from a nested route, review, or vehicle helper causes the entire storage summary to fall back to an empty object, hiding counts and history. | `ObdStoreReports.java:191-239` wraps summary construction in one catch and returns `emptyStorageSummary()` on `JSONException`. | Medium | Easy |
| 27 | Map selection can go stale | When the available routes change, the code falls back to the first route visually but does not update the selected route id, leaving chips and later actions out of sync. | `map.js:101-107` only initializes `selectedMapSessionId` when it is empty; `map.js:368-374` falls back without repairing the stored id; `map.js:218-226` compares chips to the stale id. | Low | Easy |
| 28 | Map does not refit changed coordinates | The map fit cache only uses route id and point count, so replacing route coordinates with the same number of points can leave the viewport focused on the old geometry. | `map.js:329-333` builds `fitKey` from `session.id` and `points.length` only. | Low | Easy |
| 29 | Invalid map points are not filtered | A single bad latitude/longitude can become `NaN` in Leaflet rendering because the main map maps point fields directly to numbers without validation. | `map.js:258-334` builds `latlngs` from `Number(point.lat)` and `Number(point.lng)` without finite/range filtering; `scrubber.js:83-145` likewise trusts route point coordinates. | Medium | Easy |
| 30 | On-demand route misses are cached forever | If a trip route is unavailable once, the dashboard stores `null` and will not retry later when storage updates add the route. | `panels.js:690-734` caches `null` in `onDemandRoutes` for failed route loads and returns cached values before asking native again. | Medium | Easy |

## Suggested Order

1. Fix high-risk data integrity first: backup while logging, clear while logging,
   encrypted restore expansion, JSONL-disabled session persistence, and runtime
   polling failure cleanup.
2. Fix live dashboard correctness next: stale telemetry acceptance, session
   baseline reset, stale PID re-emission, map raw-session tails, and route
   fallback selection.
3. Tighten history/reporting: latest-eight route filtering, latest-100 trips,
   stale rollups after pruning, and read-time all-session rollup rebuilds.
4. Polish lower-risk reliability: permission races, duplicated adapter history,
   invalid stored addresses, stale map selection, fit cache keys, invalid point
   filtering, and route-null retry behavior.

## Discarded Candidates

- Old Flask/PostgreSQL receiver issues: out of scope per `AGENTS.md`.
- Generated `assets/dashboard/index.html` differences: source fixes belong in
  dashboard source files/partials, not the generated artifact.
- Remote map tiles default: checked and rejected for this checkout because
  `core.js` currently defaults remote tiles to off.
- Blank adapter persistence: checked and rejected because `DeviceCatalog.remember`
  returns early for blank addresses; the validated issue is invalid nonblank
  addresses.
